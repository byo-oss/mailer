`sesMailer` sends with SES v2 `SendEmail` through a client you already have, so the mailer uses the same credentials, region and middleware as the rest of your app.

```sh
npm install @byo-oss/mailer @aws-sdk/client-sesv2
```

`@aws-sdk/client-sesv2` is an optional peer dependency, `^3.527.0`: the first version whose `SendEmail` types include custom `Headers`. It is loaded on the first send, so apps that use another adapter never need it.

```ts title="lib/mailer.ts"
import { SESv2Client } from "@aws-sdk/client-sesv2";
import { sesMailer } from "@byo-oss/mailer/ses";

export const mailer = sesMailer({
  from: "Acme Support <help@acme.com>",
  client: new SESv2Client({ region: "us-east-1" }),
});
```

If what you have is an SES v1 `SESClient`, use [`wrapsMailer`](/docs/mailer/wraps) with `client: new WrapsEmail({ client: sesClient })` instead.

## Options

| Option | Default | |
|---|---|---|
| `from` | required | Sender address, verified in SES: `"Acme <help@acme.com>"`. |
| `client` | required | Your `new SESv2Client({ ... })`, or any `{ send(command), config? }` with the same shape (a dev sink, a fake in tests). Its region (`config.region`) is read after each send, for `messageId`. |

## Errors

| `SendEmail` throws | Result |
|---|---|
| `BadRequestException`, or `MessageRejected` for the message itself. | `PermanentMailError` |
| `MessageRejected` for an address or domain that isn't verified, or a sandboxed account. | Rethrown, so it retries once you fix the account |
| Anything else: throttling, `LimitExceededException`, `SendingPausedException`, `AccountSuspendedException`, `MailFromDomainNotVerifiedException`, `NotFoundException`, network errors, missing credentials. | Rethrown, so it retries |

Headers SES owns (`From`, `To`, `Subject`, `Reply-To`, `Message-ID`, `Date`, ...) are rejected with a `PermanentMailError`. Use `replyTo` for the reply-to address.

## Result

`sesMailer` returns `{ id, messageId }`. `id` is the SES message id. `messageId` is `<id@email.amazonses.com>` when the client's region is us-east-1, the one region checked with real sends (see [Wraps](/docs/mailer/wraps#result) for why).

`messageId` is left out in other regions, with a custom `endpoint`, and for a client without a readable `config.region` (most dev sinks). If SES returns no `MessageId`, `id` is `"ses:<uuid>"` rather than a throw, which would send the message again.
